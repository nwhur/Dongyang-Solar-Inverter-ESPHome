# 📑 동양 E&P / 다스텍 태양광 인버터 RS-485 Hex 통신 프로토콜 명세서

이 문서는 동양 E&P(Dongyang E&P) 및 다스텍(Dastech) 계열 인버터의 **Hex Mode RS-485 통신 프로토콜**을 역공학 및 사양 분석을 통해 정리한 기술 문서입니다.

---

## ⚙️ 1. 통신 기본 규격 (Physical Layer)

* **인터페이스:** RS-485 2-Wire (Half-Duplex)
* **통신 속도(Baud Rate):** 9600 bps
* **데이터 비트(Data Bits):** 8 bits
* **정지 비트(Stop Bit):** 1 bit
* **패리티(Parity):** None (8-N-1)
* **흐름 제어(Flow Control):** None
* **엔디언(Endianness):** 리틀 엔디언 (Little-Endian, 하위 바이트 우선)

---

## 📤 2. 요청 프레임 규격 (Host ➜ Inverter, 7 Bytes)

ESP32가 인버터로 데이터를 요청(Poll)할 때 전송하는 질의 프레임 구조입니다.

| 오프셋 | 필드명 | 값 (Hex) | 설명 |
| :---: | :--- | :---: | :--- |
| **Byte 0** | Header 1 | `0x0A` | 요청 시작 식별자 |
| **Byte 1** | Header 2 | `0x96` | 고정 커맨드 프리앰블 |
| **Byte 2** | **Inverter ID** | `0x02` 또는 `0x61` | 대상 인버터 국번 ID (1번: 2, 2번: 97) |
| **Byte 3** | Command | `0x54` | 데이터 읽기 요청 코드 ('T') |
| **Byte 4** | Sub-Cmd | `0x18` | 측정 데이터 블록 지정 |
| **Byte 5** | Length | `0x05` | 요청 페이로드 길이 |
| **Byte 6** | **Checksum** | `CHK` | `(Byte 2(ID) + Byte 3(0x54) + Byte 4(0x18)) & 0xFF` 합산값 |

### 요청 프레임 및 체크섬 계산 규칙
동양 인버터의 요청 프레임 체크섬은 **`ID + 0x54 + 0x18`**의 1바이트 덧셈 합산값입니다. (※ 응답 프레임의 XOR 체크섬과 방식이 다름에 유의)

* **ID가 1번인 인버터 질의 (ID: 0x01):**
  `0A 96 01 54 18 05 6D` (체크섬 `0x01 + 0x54 + 0x18` = `0x6D`)
* **ID가 2번인 인버터 질의 (ID: 0x02, 기본값):**
  `0A 96 02 54 18 05 6E` (체크섬 `0x02 + 0x54 + 0x18` = `0x6E`)
* **ID가 97번인 인버터 질의 (ID: 0x61, 2대 병렬 시 2번 인버터):**
  `0A 96 61 54 18 05 CD` (체크섬 `0x61 + 0x54 + 0x18` = `0xCD`)

> 💡 **인버터 국번(ID)의 결정 원리:**
> 동양 E&P 인버터의 통신 국번(ID)은 제조사 출하 시 **인버터 본체 시리얼 번호(S/N)의 마지막 2자리 10진수 숫자**로 설정됩니다.
> (예: S/N 끝이 `...02`이면 ID=2, `...97`이면 ID=97 -> 16진수 `0x61`)

## 📥 3. 응답 프레임 규격 (Inverter ➜ Host, 32 Bytes)

인버터가 질의를 수신한 후 약 50~150ms 이내에 회신하는 32바이트 고정 길이 데이터 프레임입니다.

| 오프셋 | 필드명 | 바이트 수 | 환산 공식 및 단위 | 설명 |
| :---: | :--- | :---: | :--- | :--- |
| **0 ~ 1** | **Header** | 2 | `0xB1`, `0xB7` | 응답 프레임 고정 헤더 |
| **2** | **Inverter ID** | 1 | `0x02` / `0x61` | 응답하는 인버터의 국번 ID |
| **3 ~ 4** | DC Voltage | 2 | `(Byte4 << 8 \| Byte3) / 10.0` [V] | 태양광 모듈(PV) 직류 전압 |
| **5 ~ 6** | DC Current | 2 | `(Byte6 << 8 \| Byte5) / 10.0` [A] | 태양광 모듈(PV) 직류 전류 |
| **7 ~ 8** | Reserved | 2 | - | 내부 레지스터 (DC 출력 연산 가능) |
| **9 ~ 10** | AC Voltage | 2 | `(Byte10 << 8 \| Byte9) / 10.0` [V] | 계통 연계 교류 전압 (220V) |
| **11 ~ 12** | AC Current | 2 | `(Byte12 << 8 \| Byte11) / 10.0` [A] | 계통 연계 교류 전류 |
| **13 ~ 14** | Temperature | 2 | `(Byte14 << 8 \| Byte13) / 10.0` [°C] | 인버터 내부 방열판 온도 |
| **15 ~ 16** | **Energy Today** | 2 | `(Byte16 << 8 \| Byte15) / 100.0` [kWh] | **금일 누적 발전량 (10 Wh 단위)** |
| **17 ~ 19** | **Energy Total** | 3 | `Byte17 \| (Byte18<<8) \| (Byte19<<16)` [kWh] | **설치 후 누적 발전량 (1 kWh 단위)** |
| **20 ~ 24** | Fault / Status | 5 | 비트 플래그 | 인버터 작동 상태 및 에러 코드 |
| **25 ~ 26** | Frequency | 2 | `(Byte26 << 8 \| Byte25) / 10.0` [Hz] | 계통 교류 주파수 (60Hz) |
| **27 ~ 30** | Reserved | 4 | - | 예약 필드 |
| **31** | **Checksum** | 1 | `Byte 0 ^ ... ^ Byte 30` | **전체 0~30번 바이트의 XOR 체크섬** |

## 💡 4. 데이터 계측 특성 및 주의사항

1. **발전량 단위의 차이 (Today vs Total)**
   * **금일 발전량 (`Energy Today`):** 0.01 kWh (= 10 Wh) 단위로 누적되므로 발전이 일어나는 동안 거의 실시간(수 분 단위)으로 정밀하게 카운트가 올라갑니다.
   * **누적 발전량 (`Energy Total`):** 인버터 내부 H/W 레지스터 사양상 **정수 1 kWh** 단위로만 기록됩니다. 따라서 일일 20 kWh 발전 시 하루에 약 20번만 계측값이 갱신됩니다.
2. **야간 인버터 슬립 (Shutdown)**
   * 태양광 인버터는 일몰 후 PV 패널에서 전력이 공급되지 않으면 스스로 내부 전원을 끄고 슬립(Sleep) 상태로 전환됩니다.
   * 이때 RS-485 질의 시 무응답(Timeout)이 발생하므로, 펌웨어에서는 발전 출력을 0W로 정상 표기하고 발전량 누적 통계는 NVS에 보존된 값을 유지해야 합니다.
3. **프레임 동기화 (Sliding Window Algorithm)**
   * 긴 통신선에서 발생하는 전기적 노이즈나 인버터 부팅 시 쓰레기 바이트(Garbage Byte)가 버퍼에 섞여 들어올 수 있습니다.
   * 수신 버퍼에서 `0xB1 0xB7` 헤더가 나올 때까지 선두 바이트를 버리는 **슬라이딩 윈도우(Sliding Window)** 알고리즘을 적용해야 CRC 에러 없이 100% 정상 수신이 유지됩니다.
